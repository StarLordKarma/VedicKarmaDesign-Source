# Vedic Astrology Booking — история проекта

**Статус документа:** актуальное описание исходного кода на август 2026 года. **Автор:** Manus AI. Этот документ фиксирует реализованные возможности и технические решения, а не является юридической, налоговой или лицензионной консультацией.

## 1. Назначение продукта

Vedic Astrology Booking — многоязычная платформа для приёма заказов на персональные ведические астрологические разборы. Клиент выбирает пакет **Basic** либо **Basic+ с нумерологическим дополнением**, вводит данные рождения, принимает уведомление о конфиденциальности и переходит к криптовалютной оплате. После подтверждённой оплаты владелец может контролировать подготовку и отправку многостраничного PDF-отчёта.

На текущей версии публичная часть работает на английском, русском, немецком и испанском языках. Язык, тема и безопасный черновик формы сохраняются в браузере. Согласие на обработку данных не восстанавливается автоматически после обновления страницы: его необходимо подтверждать отдельно.

| Контур | Что реализовано | Основные точки кода |
|---|---|---|
| Публичный заказ | Выбор пакета, валюты, промокода, ввод данных рождения, итоговая стоимость, review-before-submit, загрузочный и success-сценарии | `client/src/pages/Home.tsx`, `shared/booking.ts` |
| Языки и доступность | EN/RU/DE/ES, сохранение языка, локализованные форматы дат и валют, подсказки и валидация | `client/src/pages/Home.tsx`, `client/src/pages/Privacy.tsx` |
| Криптооплата | Создание NOWPayments checkout и проверка IPN на сервере | `server/payment-flow.ts`, `server/routers.ts` |
| Администрирование | Owner-only данные клиентов, доставка PDF, поиск, фильтры, экспорт, история изменений и pricing | `client/src/pages/Admin.tsx`, `server/routers.ts` |
| Report Studio | Очередь отчётов, детерминированные расчёты, narrative JSON, PDF, owner approval и отправка | `server/report-studio-*`, `client/src/pages/ReportStudio.tsx` |
| Payment Test Lab | Изолированная подпись IPN, audit log, retention, preview, cleanup history и CSV export | `client/src/pages/PaymentTestLab.tsx`, `server/payment-ipn-test-harness.ts` |

## 2. Как развивался проект

Первый этап сформировал базовую воронку: публичный сайт, booking form, пакеты услуг, криптовалютный checkout, owner-only workspace и доставку подготовленного PDF. Затем были добавлены локализация, экспорт записей, история клиента, фильтры, мобильные действия, сохранение черновиков и privacy-элементы интерфейса.

Второй этап сместил фокус на управляемое производство отчётов. Появились service packages с версиями и безопасной активацией, Report Studio, синтетические задания для проверки PDF без отправки клиенту и изолированный Payment Test Lab. В такой схеме внешний платёжный провайдер, генерация текста и отправка файлов отделены друг от друга и не запускаются тестовым IPN-симулятором.

| Период / этап | Добавленные результаты | Сохранённые ограничения |
|---|---|---|
| Базовый сайт | Локализованная landing page и booking flow, Basic/Basic+ | Клиентские данные не должны использоваться в публичных URL или логах |
| Оплата и owner workspace | NOWPayments checkout/IPN, PDF delivery через Resend, клиентские записи | Все административные операции защищены серверным owner guard |
| Операционное удобство | Поиск, фильтры, CSV/PDF exports, drafts, activity dashboard, SLA tools | Исторические snapshot цен и заказов остаются неизменяемыми |
| Report Studio | Очередь jobs, Lahiri/Vimshottari D1/D9 facts, narrative JSON, owner approval | Автоматическая обработка управляется настройкой и требует наблюдения владельца |
| Payment Test Lab | Подписанная simulation, audit, 90-day default retention, managed cleanup | Тест не делает provider call, не переводит средства и не отправляет клиентские письма |
| Последние изменения | Локализованные cleanup emails, owner email language selector, cleanup history/CSV, pricing comparison dialog | Email template содержит только количество удалённых записей и срок хранения, без payload/ключей |

## 3. Текущая бизнес-конфигурация

Управление ценами находится в owner-only Admin workspace. Цены хранятся по валютам и имеют историю изменения: старая цена, новая цена, время и actor. В публичном checkout используются текущие server-derived значения, а не локальные значения браузера.

| Валюта | Статус текущей конфигурации | Примечание |
|---|---|---|
| USD | Basic **$15**, add-on **$10** | Установлено через audited pricing flow в текущем проекте |
| EUR | Отдельная конфигурация | Не менялась при последнем USD-обновлении |
| GBP | Отдельная конфигурация | Не менялась при последнем USD-обновлении |

Перед сохранением цены в Admin открывается модальное окно. Оно показывает для выбранной валюты **текущую → предложенную** цену Basic, add-on и итог checkout. Изменение становится постоянным только после подтверждения и проходит через защищённую server procedure.

## 4. Безопасность и данные

Сервер различает public и admin операции. Административный интерфейс не является единственной защитой: tRPC procedures для владельца проверяют `OWNER_OPEN_ID` на сервере. Не ослабляйте это ограничение при переносе проекта.

Privacy UI фиксирует выбранный locale, версию notice и время acknowledgement на серверной стороне при создании заказа. Текст privacy/disclaimer необходимо продолжать проверять у квалифицированного юриста для стран целевой аудитории; разработка не создаёт гарантии соответствия конкретному законодательству.

| Данные / секреты | Где должны находиться | Чего делать нельзя |
|---|---|---|
| Database URL, OAuth и JWT | Secret manager среды развёртывания | Коммитить в Git или класть в ZIP |
| NOWPayments API/IPN secret | Только server environment | Отдавать в клиентский bundle |
| Resend API key | Только server environment | Добавлять в историю audit или email body |
| PDF-файлы и пользовательские данные | Приватное S3-compatible storage / production DB | Хранить байты PDF в исходном коде |
| Owner identity | `OWNER_OPEN_ID` среды | Заменять проверку только UI-ролью |
