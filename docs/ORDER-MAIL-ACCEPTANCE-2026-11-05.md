# Приёмка цепочки писем — песочница, 5 ноября 2026

Реализована цепочка: новое оформление → проверенная оплата/явное принятие поступления → единственное локализованное письмо о принятии → подготовка PDF → разрешение на точную версию/адресата → ожидание → единственное итоговое письмо.

Без контактов в первом письме. Интервалы: tarot 15–20, western 15–30, vedic 20–40 минут; выбираются один раз и сохраняются. Отсчёт после принятия первого письма сервисом. Ручное одобрение и автоматическая проверка качества не заменяются таймером. Защита времени действует в очереди, центральной отправке и приватном скачивании. Старые заказы не включаются задним числом.

Владелец: /owner/order-flow, переходы из Control Room / Report Studio / RiskPay. Видны текущий этап, подтверждение поступления и принятия, первое письмо/попытки/ошибки/provider ID, подготовка, одобренный PDF/hash, срок и результаты доставки. Отдельно отмечена приостановка. Доставка во входящие не заявляется без доказательства; «принято сервисом» отображается явно.

Рекомендации включаются отдельным необязательным согласием. Предыдущие покупки учитываются через подписанную историю из ссылок писем, привязанную к получателю. По одному введённому email история не раскрывается. Для старых несвязанных заказов полная история неизвестна: исключается текущая услуга, предлагаются другие направления; не делается заявление «вы никогда этого не заказывали».

## Проверки

- Полный unit-набор: 630 passed, 25 skipped в момент запуска (20 ранее условных проверок и 5 новых SQL-кейсов). Затем SQL-набор расширен до 7 новых кейсов и выполнен отдельно.
- Финальный SQL-набор: 32 passed (7 новых lifecycle + 6 pipeline concurrency + 2 Control Room + 17 admin; 7 admin-проверок перекрываются с unit-набором).
- Всего 655 уникальных Vitest-проверок прошли при объединении наборов. Две внешние credential-пробы Resend/NOWPayments не запускались. Результаты не означают проверку реальной почты или денег.
- После последних правок — 76 targeted passed: lifecycle/copy/history, client status, immutable mail outbox, Report Studio, manual RiskPay policy.
- Финальный Playwright: 2 passed (47.8 s). Проверены оба решения владельца, конкурентные нажатия, первое письмо и его язык, отсутствие контактов/вложения в первом, запрещённый ранний download, точные PDF-байты/hash, отложенная итоговая доставка, ровно два письма в отдельном mock, рекламный блок и подписанные ссылки, отказ неверным email/version, смена адресата и возврат. Сделаны desktop/mobile снимки общего обзора владельца.
- TypeScript и production build прошли; git diff --check прошёл.
- Миграции с нуля прошли на отдельной локальной БД sandbox_order_mail_test.

Для проверки границы задержки время сдвигалось исключительно в локальной SQL-фикстуре с сохранением согласованности acceptedAt/ackAcceptedAt/delay/dueAt. Полное реальное ожидание 15–40 минут не проводилось. Сам код не содержит production-переключателя ускорения или ранней выдачи.

## Найденные и исправленные проблемы во время разработки

- Нельзя проверять срок только в worker: добавлен центральный guard и запрет раннего клиентского скачивания.
- Нельзя полагаться на таймер процесса: состояние и lease сохраняются в БД до сетевого запроса, повторы используют прежние bytes/key.
- Нельзя считать факт callback принятием суммы: RiskPay по-прежнему требует первого решения владельца.
- Раздельные новые БД со старым bucket дают коллизии outbox ID: выделены отдельные bucket и mail mock. Проверка целостности остановила ошибочную тестовую отправку; protection не ослаблялась.
- Первый браузерный тест ожидал несуществующий statusUrl в синтетической fixture; исправлен на фактическую ссылку первого письма.
- У SQL-фикстуры исправлены недопустимые для MySQL timestamp 1970-01-01; тестовый timeout увеличен до 30 s для конкурентных интеграций.
- Ошибка размещения новой проверки целостности временно блокировала первое письмо в локальном тесте; SQL-набор обнаружил её. Проверка перенесена в gate итоговой доставки, финальный набор прошёл.
- Восстановление очереди учитывает все общие оплаченные статусы, а не только confirmed/finished.

## Что не выполнялось

Production deploy/configuration, AGPL mirror публикация этой новой версии, реальные списания, переводы, реальные покупательские письма, реальный возврат и банковский спор не выполнялись. Изменения действуют только в новой песочнице. Публикация после отдельного согласования результата, по runbook с миграцией до включения флагов.
