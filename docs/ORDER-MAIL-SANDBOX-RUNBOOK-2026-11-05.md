# Два письма и отложенная выдача: песочница

Рабочая ветка: `codex/order-mail-schedule-2026-11-05`. Production не меняется до согласования.

## Что изменено

Новые заказы при ORDER_MAIL_LIFECYCLE_ENABLED=true получают версионированный маркер в снимке цены. После подтверждения оплаты (для RiskPay — после явного принятия поступления владельцем) создаётся единственная запись order_mail_flows. Она хранит неизменяемый адресат/язык/снимок заказа, случайный интервал, точный текст первого письма, попытки, идентификатор провайдера, время принятия письма и срок выдачи. Заказ, не включённый в цепочку при checkout, не получает её задним числом.

Первое письмо: номер и направление заказа, принятие в работу, интервал, предупреждение о возможной дополнительной проверке и приватная ссылка. Контактов для обращения нет. Переводы en/ru/es/de. Отсчёт от принятия письма сервисом, не от callback или оплаты.

Таро 15–20 минут, западная астрология 15–30, ведическая 20–40. Генерация PDF не задерживается. В manual-режиме второе одобрение владельца остаётся обязательным и разрешает только version/hash/recipient; раннее одобрение планирует отправку. Позднее одобрение не заставляет ждать второй случайный интервал. В automatic-режиме существующие проверки качества и разрешение автоматической выдачи сохраняются; общий guard проверяется перед самой отправкой, в том числе под блокировкой заказа. Отмена, возврат или смена исходных данных блокируют выдачу.

Первое письмо имеет постоянный ключ и сохранённый payload. Перед сетью фиксируется lease и время первой попытки. При сбое после возможного принятия повторяется та же отправка; после 23 часов требуется сверка. Итоговая доставка использует существующий immutable PDF outbox и idempotency key; автоматические повторы останавливаются при постоянной ошибке или по истечении часа. Состояние sent в БД означает принятие почтовым сервисом, не гарантирует попадание во входящие. Отдельный webhook delivered в этой работе не добавлялся.

Клиентский PDF не доступен раньше срока через приватный маршрут скачивания. Предпросмотр владельца остаётся доступным.

## Видимость владельцу

`/owner/order-flow`: общий обзор до 200 последних заказов с отдельными состояниями оплаты, поступления, принятия, первого письма, попыток/ошибок, подготовки, одобренной версии/SHA-256, назначенного срока и итоговых попыток доставки. Доступ к данным API только для существующего владельца/admin. HTML-оболочка без данных доступна, API без владельца возвращает 403. Приватные ответы no-store/no-referrer/noindex.

Control Room, Report Studio и RiskPay queue имеют переход в общий обзор. Report Studio получает отдельный безопасный orderFlow DTO; клиентские приватные страницы получают только состояние первого письма и назначенное время. Внутренние адресаты, ошибки, payload и provider ID клиенту не раскрываются.

## Рекомендации

Отдельный необязательный checkbox на странице checkout. Оплаченный PDF доставляется независимо от выбора рекомендаций. В итоговом письме — до двух других направлений, без заявления о гарантированном отсутствии всех прошлых заказов.

Для возврата из письма добавляется подписанная история уже оплаченных услуг, привязанная к адресату без его открытого email. При следующем заказе сервер проверяет подпись, срок и совпадение адресата; эти услуги исключаются из предложений. История не ищется по неподтверждённому введённому email. Старые заказы до этой системы и заказы, оформленные без перехода по ссылке из предыдущего письма, связать достоверно нельзя: в таком случае исключается текущая услуга и предлагаются другие направления. При отсутствии ORDER_SIGNING_SECRET история не выпускается; письмо/PDF продолжают работать.

## Изоляция и запуск

- БД: только `sandbox_order_mail_test` на localhost:3308.
- MinIO: отдельный `vedic-order-mail-sandbox` на localhost:9010.
- Почта: отдельный mock на localhost:4012. Реальных писем нет.
- Приложение: localhost:4092.
- Конфигурация читается в память из существующего локального файла песочницы; секреты не копируются и не сохраняются в новый env-файл.

`scripts/order-mail-sandbox.mjs` требует локальные DB/storage/email/AI, sandbox auth и RISKPAY_LIVE_ENABLED=false. Путь к существующей синтетической конфигурации задаётся ORDER_MAIL_SANDBOX_ENV. Он переключает DB/bucket/порт на указанные выше отдельные ресурсы.

Пример для этого рабочего окружения:

```
ORDER_MAIL_SANDBOX_ENV=/private/tmp/karma-riskpay-release-20261103/.env.card-sandbox node scripts/order-mail-sandbox.mjs dist/index.js
```

Почтовый mock запускается отдельно:

```
MOCK_PORT=4012 MOCK_HOST=127.0.0.1 node scripts/sandbox-mock-server.mjs
```

Миграции — тем же wrapper с `--import tsx server/migrate.ts`; начальные синтетические записи — `--import tsx scripts/seed-sandbox.ts`. Seed допустим только в новой выделенной базе; не запускать его на рабочей БД. Bucket создаётся отдельно штатным S3 CreateBucketCommand локального MinIO.

В этой машине исходная конфигурация зафиксирована как localhost / vedic_card_sandbox / sandbox auth / локальные mock endpoints. Production-конфигурация не читалась и не использовалась.
